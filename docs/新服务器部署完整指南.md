# 算小智 — 新服务器从零部署完整指南

> 本文档基于实际部署踩坑记录编写，覆盖从空白服务器到应用上线的全过程。

---

## 项目速览

| 组件 | 技术 | 端口 |
|------|------|------|
| 前端 | React 19 + Vite 7 + TypeScript + Tailwind CSS | 生产由 Express 托管 |
| 后端 | Express 4 + Prisma 5 + tsx | 3000 |
| 数据库 | PostgreSQL | 5432 |
| 进程管理 | PM2 | — |
| 包管理 | pnpm | — |

**架构特点**：Express 在生产模式下自动托管前端 `dist/` 静态文件（见 `server/src/app.ts`），因此只需暴露一个端口 3000 即可服务整个应用。

## 准备工作

### 你需要准备的

- 服务器 SSH 登录凭据（IP、用户名、密码或密钥）
- DeepSeek API Key（AI 功能需要）
- 本地 Windows 需装有 OpenSSH Client（Win10/11 自带，没有的话管理员 PowerShell 执行 `Add-WindowsCapability -Online -Name OpenSSH.Client~~~~0.0.1.0`）

### 部署包制作（本地执行）

在项目根目录打包，排除不需要的文件：

```powershell
cd C:\Users\DaiYuan\Desktop\算小智2.1
tar -czf suanxiaozhi-deploy.tar.gz --exclude='node_modules' --exclude='.git' --exclude='dist' --exclude='coverage' --exclude='*.db' --exclude='*.db-shm' --exclude='*.db-wal' --exclude='.DS_Store' --exclude='Thumbs.db' --exclude='*.log' --exclude='docs' --exclude='.env' --exclude='.claude' .
```

打包后约 3.6 MB，包含 260+ 个文件。

## 第一阶段：服务器基础环境

### 1.1 SSH 登录

```powershell
ssh ubuntu@<服务器IP>
```

### 1.2 安装 Node.js（推荐方案：nvm）

```bash
# 下载 nvm 安装脚本（不要用 curl | bash 管道，有安全风险）
curl -o /tmp/nvm-install.sh -fsSL https://raw.githubusercontent.com/nvm-sh/nvm/v0.40.3/install.sh
bash /tmp/nvm-install.sh

# 加载 nvm
export NVM_DIR="$HOME/.nvm"
[ -s "$NVM_DIR/nvm.sh" ] && . "$NVM_DIR/nvm.sh"

# 安装 Node.js 20 LTS
nvm install 20
nvm use 20
nvm alias default 20

# 验证
node -v  # 应显示 v20.x.x
npm -v
```

**踩坑记录**：`curl https://xxx | sudo -E bash -` 这种管道方式有安全隐患，且可能在网络不稳定时执行残缺脚本。用 nvm 更安全且支持多版本切换。

### 1.3 配置 npm 全局路径（避免权限错误）

```bash
mkdir -p ~/.npm-global
npm config set prefix ~/.npm-global
echo 'export PATH=$HOME/.npm-global/bin:$PATH' >> ~/.bashrc
source ~/.bashrc
```

**踩坑记录**：直接 `npm install -g` 会报 `EACCES: permission denied, mkdir '/usr/lib/node_modules/...'`，因为全局安装需要 root 权限。配置用户级路径后无需 sudo。

### 1.4 安装 pnpm 和 PM2

```bash
npm install -g pnpm pm2
pnpm -v    # 验证
pm2 -v     # 验证
```

### 1.5 安装并配置 PostgreSQL

```bash
# 安装
sudo apt update
sudo apt install -y postgresql postgresql-contrib

# 启动
sudo systemctl enable postgresql
sudo systemctl start postgresql

# 创建数据库和用户
sudo -u postgres psql <<EOF
CREATE USER suanxiaozhi WITH PASSWORD '你的强密码';
CREATE DATABASE suanxiaozhi OWNER suanxiaozhi;
GRANT ALL PRIVILEGES ON DATABASE suanxiaozhi TO suanxiaozhi;
\c suanxiaozhi
GRANT ALL ON SCHEMA public TO suanxiaozhi;
EOF

# 验证连接
psql postgresql://suanxiaozhi:<密码>@localhost:5432/suanxiaozhi -c "SELECT 1;"
```

> ⚠️ **安全提醒**：生产环境务必替换为强密码，不要使用 `suanxiaozhi123`。

### 1.6 配置防火墙

```bash
sudo ufw allow 22/tcp    # SSH
sudo ufw allow 80/tcp    # HTTP
sudo ufw allow 443/tcp   # HTTPS
sudo ufw allow 3000/tcp  # 应用端口
sudo ufw enable
sudo ufw status
```

## 第二阶段：部署应用代码

### 2.1 上传压缩包（本地 PowerShell 执行）

```bash
scp C:\Users\DaiYuan\Desktop\suanxiaozhi-deploy.tar.gz ubuntu@<服务器IP>:/tmp/
```

**踩坑记录**：`scp` 命令在本地执行（上传到服务器），不要在 SSH 到服务器后执行。方向是 `scp <本地文件> <远程目标>`。

### 2.2 解压

```bash
sudo mkdir -p /opt/SuanXiaoZhi
sudo chown -R $USER:$USER /opt/SuanXiaoZhi
tar -xzf /tmp/suanxiaozhi-deploy.tar.gz -C /opt/SuanXiaoZhi
cd /opt/SuanXiaoZhi
ls -la  # 确认文件完整
```

### 2.3 创建生产环境 .env

```bash
cat > /opt/SuanXiaoZhi/.env <<'EOF'
NODE_ENV=production
PORT=3000
DATABASE_URL=postgresql://suanxiaozhi:<密码>@localhost:5432/suanxiaozhi?schema=public
ALLOWED_ORIGINS=http://<服务器IP>:3000

DEEPSEEK_API_KEY=<你的DeepSeek API Key>
DEEPSEEK_BASE_URL=https://api.deepseek.com
DEEPSEEK_MODEL=deepseek-chat

AUDIT_BATCH_SIZE=20
AUDIT_FLUSH_MS=4000
EOF
```

**必须修改**：
- `DATABASE_URL`：替换数据库密码
- `DEEPSEEK_API_KEY`：替换为真实 Key
- `ALLOWED_ORIGINS`：替换为服务器 IP 或域名

### 2.4 安装依赖 & 数据库迁移 & 构建

```bash
cd /opt/SuanXiaoZhi

# 安装依赖
pnpm install

# 运行数据库迁移（创建表结构）
npx prisma migrate deploy --schema server/prisma/schema.prisma

# 生成 Prisma Client
npx prisma generate --schema server/prisma/schema.prisma

# 构建前端
pnpm build

# 验证构建产物
ls dist/index.html && echo "BUILD OK"

# 初始化种子数据（demo 账号、分类等）
pnpm seed
```

### 2.5 启动服务

```bash
# 启动（单进程，Express 同时托管前后端）
pm2 start "pnpm start" --name suanxiaozhi --cwd /opt/SuanXiaoZhi

# 保存 PM2 配置（开机自启恢复）
pm2 save
pm2 startup systemd -u $USER --hp $HOME
```

### 2.6 验证部署

```bash
# PM2 状态
pm2 status
# suanxiaozhi 应显示 status: online

# 健康检查
curl http://127.0.0.1:3000/health
# 应返回: {"ok":true}

# 前端页面
curl -s -o /dev/null -w "HTTP %{http_code}" http://127.0.0.1:3000/
# 应返回: HTTP 200
```

浏览器访问 `http://<服务器IP>:3000`，用 `demo_owner / demo123` 登录测试。

## 第三阶段：常见踩坑与解决

### 坑 1：npm 全局安装权限错误

**现象**：
```
npm error EACCES: permission denied, mkdir '/usr/lib/node_modules/pm2'
```

**解决**：配置用户级 npm 全局路径（见 1.3 节）。

### 坑 2：服务器跑 scp 报错

**现象**：
```
ssh: Could not resolve hostname c: Temporary failure in name resolution
```

**原因**：`scp` 应该在本地终端执行（上传到服务器），不是在 SSH 到服务器后执行。

**正确做法**：在 Windows PowerShell 中运行：
```powershell
scp C:\path\to\file ubuntu@<IP>:/remote/path/
```

### 坑 3：sed -i 在服务器上修改文件

如果需要快速修复单个文件，可以用 `sed` 直接在服务器改，但复杂的修改建议用 scp 传本地已改好的文件。

```bash
# 快速替换示例
sed -i 's/旧字符串/新字符串/' /path/to/file
grep '新字符串' /path/to/file  # 验证
pm2 restart suanxiaozhi
```

### 坑 4：curl 测试 API 时 token 变量未替换

**现象**：
```bash
TOKEN=$(...)  # 变量为空
curl -H "Authorization: Bearer $TOKEN"  # 实际发送了 "Bearer " 或 "Bearer <TOKEN>"
```

**正确做法**：先确认变量有值：
```bash
TOKEN=$(curl -s ... | grep -o '"token":"[^"]*"' | cut -d'"' -f4)
echo "Token: $TOKEN"  # 确认有值
curl -s -H "Authorization: Bearer $TOKEN" ...
```

### 坑 5：新增交易报 500 错误

**现象**：浏览器提交交易时 `POST /api/v1/mobile/transactions` 返回 `500 Internal Server Error`。

**根因**：前端传的 `accountId`（如 `icbc-savings`、`alipay`）是硬编码的虚拟标识，不是数据库 `Ledger` 表中真实存在的 ID。PostgreSQL 外键约束拒绝无效引用。

**修复**（已在代码中修复）：后端在 `server/src/routes/v1/mobile/transactions.ts` 中先验证 `ledgerId` 是否存在，不存在则置空。

**快速诊断命令**：
```bash
# 登录拿 token
TOKEN=$(curl -s -X POST http://127.0.0.1:3000/api/v1/mobile/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"demo_owner","password":"demo123"}' | grep -o '"token":"[^"]*"' | cut -d'"' -f4)

# 测试创建交易（不传 accountId 可以绕过外键约束）
curl -s -X POST http://127.0.0.1:3000/api/v1/mobile/transactions \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $TOKEN" \
  -d '{"amount":5000,"type":"EXPENSE","time":"2026-06-03T12:00:00.000Z","categoryName":"food","description":"测试"}'
# 返回 {"ok":true,...} 说明后端正常，问题在前端传的参数
```

### 坑 6：category vs categoryName 字段映射

**现象**：前端传 `"category":"transfer"`，后端读取 `body.categoryName`，导致分类一直显示"未分类"。

**修复**（已在代码中修复）：后端 `transactions.ts` 中改为 `body.categoryName ?? body.category ?? "未分类"`。

### 坑 7：PM2 日志中的 ELIFECYCLE 错误

**现象**：`pm2 logs` 看到 `ELIFECYCLE Command failed`。

**原因**：服务器首次启动时 `initDB()` 可能因数据库未就绪或迁移未执行而崩溃，PM2 自动重启后恢复正常。

**检查**：如果 `pm2 status` 显示 `online` 且 `restart` 次数稳定（不再增加），则已正常。

## 更新部署流程

每次推送代码后，有两种方式更新服务器：

### 方式 A：完整重部署（推荐）

```powershell
# 本地重新打包
cd C:\Users\DaiYuan\Desktop\算小智2.1
tar -czf suanxiaozhi-deploy.tar.gz --exclude='node_modules' --exclude='.git' --exclude='dist' --exclude='.env' --exclude='.claude' .
scp suanxiaozhi-deploy.tar.gz ubuntu@<IP>:/tmp/
```

```bash
# 服务器解压覆盖
cd /opt/SuanXiaoZhi
tar -xzf /tmp/suanxiaozhi-deploy.tar.gz
pnpm install
npx prisma migrate deploy --schema server/prisma/schema.prisma
npx prisma generate --schema server/prisma/schema.prisma
pnpm build
pm2 restart suanxiaozhi
```

### 方式 B：单文件更新

```powershell
scp C:\path\to\changed\file.ts ubuntu@<IP>:/opt/SuanXiaoZhi/path/to/file.ts
```

```bash
# 服务器
cd /opt/SuanXiaoZhi
pnpm build  # 如果改了前端
pm2 restart suanxiaozhi
```

## 快速排查清单

遇到问题时按顺序检查：

1. **服务是否在运行？** → `pm2 status`
2. **端口是否监听？** → `curl http://127.0.0.1:3000/health`
3. **数据库是否可连接？** → `psql postgresql://suanxiaozhi:<密码>@localhost:5432/suanxiaozhi -c "SELECT 1;"`
4. **迁移是否执行？** → `npx prisma migrate status --schema server/prisma/schema.prisma`
5. **防火墙是否放行？** → `sudo ufw status`
6. **PM2 错误日志？** → `pm2 logs suanxiaozhi --lines 50`
7. **API 是否正常？** → 用 curl 测试（见坑 5 的示例命令）
8. **前端构建产物？** → `ls /opt/SuanXiaoZhi/dist/index.html`
