# 算小智 全量测试文档

> 版本: v1.0 | 日期: 2026-06-03 | 测试范围: 全系统

---

## 一、测试目标

验证以下核心功能在清空数据重新播种后的正确性：

1. **认证系统** — 注册、登录、Token 校验、角色识别
2. **RBAC 权限** — 角色→权限映射、路由守卫、API 鉴权
3. **交易 CRUD** — 创建、查看、编辑、删除、异常检测
4. **家庭数据共享** — 家庭成员可查看老人账本交易、流水
5. **分析/统计** — 消费摘要、趋势、洞察
6. **规划管理** — 理财计划 CRUD（含 family 权限验证）
7. **账户管理** — 账本 CRUD
8. **产品/风控** — 产品浏览、推荐、估算、风险评估
9. **激励机制** — 任务、成就、积分
10. **管理员功能** — 用户管理、交易审计、产品管理、报表、系统监控
11. **前端关键流程** — 登录→首页→记账→分析→规划 全链路

## 二、测试环境

### 2.1 数据库重置

```bash
# 删除旧数据库
rm -f server/prisma/dev.db server/prisma/dev.db-journal server/prisma/dev.db-wal

# 重建迁移
pnpm prisma migrate dev --schema server/prisma/schema.prisma --name restore_business_models

# 生成 Prisma Client
pnpm prisma generate --schema server/prisma/schema.prisma
```

### 2.2 种子数据规模

| 实体 | 数量 | 说明 |
|------|------|------|
| 角色 | 5 | owner, family, super_admin, operator, viewer |
| 用户 | 8 | 6 个 demo 用户 + 2 个新增测试用户 |
| 家庭 | 2 | 演示家庭（3人）+ 测试家庭（2人） |
| 账本 | 8 | 每人 1 个个人账本 + 2 个家庭共享账本 |
| 分类 | 14 | 8 支出 + 4 收入 + 2 转账 |
| 交易 | ~600 | owner 200条 + family 150条 + admin 80条 + 分散其他 |
| 产品 | 6 | 3 个原始 + 3 个新增（含 1 个已下架） |
| 任务 | 6 | 4 个原始 + 2 个新增 |
| 成就 | 5 | 3 个原始 + 2 个新增 |
| 提醒 | ~10 | 每用户 2 条自动种子 + 手动创建 |
| Persona | 4 | 不同风险等级 |
| 风险评估 | 3 | NEW / COMPLETED / CANCELLED |
| 聊天会话 | 3 | 含历史消息 |
| 审计事件 | ~15 | 多用户多操作 |

### 2.3 交易数据分布

金额范围（分）:
- 小额: 100 - 5000 (¥1 - ¥50) — 40%
- 中额: 5000 - 50000 (¥50 - ¥500) — 35%
- 大额: 50000 - 200000 (¥500 - ¥2000) — 15%
- 超大额（异常）: 200000 - 1000000 (¥2000 - ¥10000) — 10%

时间范围: 近 120 天

## 三、测试用例

### 模块 A: 认证系统 (Auth)

#### A1. 注册新用户
- **请求**: POST /api/v1/mobile/auth/register { username: "test_new_user", password: "test123" }
- **预期**: 200, 返回 { id, username }, role 默认为 "owner"
- **验证**: 数据库 User 表存在该记录

#### A2. 重复注册
- **请求**: 用已有用户名再次注册
- **预期**: 409 或 400, message 包含 "already exists" 或 "duplicate"

#### A3. 空用户名/密码注册
- **请求**: POST /api/v1/mobile/auth/register { username: "", password: "" }
- **预期**: 400, validation error

#### A4. 登录 — owner
- **请求**: POST /api/v1/mobile/auth/login { username: "demo_owner", password: "demo123" }
- **预期**: 200, { ok: true, token: "token-{id}", role: "owner" }

#### A5. 登录 — family
- **请求**: POST /api/v1/mobile/auth/login { username: "demo_family", password: "demo123" }
- **预期**: 200, { ok: true, token: "token-{id}", role: "family" }

#### A6. 登录 — admin
- **请求**: POST /api/v1/mobile/auth/login { username: "demo_admin", password: "demo123" }
- **预期**: 200, { ok: true, token: "token-{id}", role: "super_admin" }

#### A7. 错误密码登录
- **请求**: POST /api/v1/mobile/auth/login { username: "demo_owner", password: "wrong" }
- **预期**: 401, ok: false

#### A8. 不存在的用户登录
- **请求**: POST /api/v1/mobile/auth/login { username: "nobody", password: "xxx" }
- **预期**: 401

#### A9. 获取当前用户信息
- **请求**: GET /api/v1/mobile/auth/me (Bearer token)
- **预期**: 200, { id, username, role, points, isActive }

#### A10. 无效 Token 访问
- **请求**: GET /api/v1/mobile/auth/me (Bearer token-invalid)
- **预期**: 401

### 模块 C: 交易系统 (Transactions)

#### C1. 创建支出交易
- **请求**: POST /api/v1/mobile/transactions { amountCent: 4500, type: "EXPENSE", categoryName: "餐饮", note: "午餐" }
- **预期**: 201, 返回 transactionId

#### C2. 创建收入交易
- **请求**: POST /api/v1/mobile/transactions { amountCent: 500000, type: "INCOME", categoryName: "工资" }
- **预期**: 201

#### C3. 创建转账交易
- **请求**: POST /api/v1/mobile/transactions { amountCent: 100000, type: "TRANSFER", ledgerId: "xxx", targetLedgerId: "yyy" }
- **预期**: 201

#### C4. 交易列表 — 分页
- **请求**: GET /api/v1/mobile/transactions?page=1&size=20 (token=demo_owner)
- **预期**: 200, total > 100, list.length = 20

#### C5. 交易列表 — 按分类筛选
- **请求**: GET /api/v1/mobile/transactions?categoryName=餐饮 (token=demo_owner)
- **预期**: 200, 返回的 list 中所有 categoryName = "餐饮"

#### C6. 交易列表 — 按时间范围
- **请求**: GET /api/v1/mobile/transactions?from=2026-01-01&to=2026-03-31
- **预期**: 200, 返回该时间范围内的交易

#### C7. 交易编辑
- **请求**: PATCH /api/v1/mobile/transactions/:id { categoryName: "购物", note: "更新备注" }
- **预期**: 200, 返回更新后的数据

#### C8. 交易删除
- **请求**: DELETE /api/v1/mobile/transactions/:id
- **预期**: 200, { deleted: true }
- **验证**: 再次 GET 确认已删除

#### C9. 异常检测 — 返回大额交易
- **请求**: GET /api/v1/mobile/transactions/anomaly-scan?since=2026-01-01 (token=demo_owner)
- **预期**: 200, anomalies 数组包含金额 > 200000(分) 的交易 ID

#### C10. 异常检测 — family 只看到可访问范围内的异常
- **请求**: GET /api/v1/mobile/transactions/anomaly-scan (token=demo_family)
- **预期**: 200, anomalies 全部属于 family 可访问的账本

```bash
# 重置数据

# 按模块运行
pnpm test -- tests/auth.spec.ts

pnpm test -- tests/transactions.spec.ts
```
