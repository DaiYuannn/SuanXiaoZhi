# 一次性补齐清单（按优先级）

## P0（先做，直接恢复主流程可用）

### 1) 账户管理接口补齐（当前为前端占位）
- 目标：替换前端本地 Promise 占位，实现真实账户 CRUD。
- 现状证据：`src/shared/constants/endpoints.ts` 中 `fetchAccounts/createAccount/updateAccount/deleteAccount` 仍返回占位数据。
- 新增后端路由文件：
  - `server/src/routes/v1/mobile/accounts.ts`
- 路由挂载点：
  - `server/src/routes/index.ts` 新增 `router.use("/api/v1/mobile/accounts", mobileAccountsRouter)`
- 接口定义（建议）：
  - GET `/api/v1/mobile/accounts`
  - POST `/api/v1/mobile/accounts`
  - PATCH `/api/v1/mobile/accounts/:id`
  - DELETE `/api/v1/mobile/accounts/:id`
- 前端替换点：
  - `src/shared/constants/endpoints.ts`
    - `fetchAccounts` -> GET `/api/v1/mobile/accounts`
    - `createAccount` -> POST `/api/v1/mobile/accounts`
    - `updateAccount` -> PATCH `/api/v1/mobile/accounts/:id`
    - `deleteAccount` -> DELETE `/api/v1/mobile/accounts/:id`

### 2) 规划能力后端落地（生成 + 列表 + 更新 + 删除 + 进度）
- 目标：去掉规划相关本地 mock，恢复服务端闭环。
- 现状证据：`src/shared/constants/endpoints.ts` 中 `fetchPlans/createPlan/updatePlan/deletePlan/generatePlans/fetchPlanProgress` 仍为本地兜底。
- 新增后端路由文件：
  - `server/src/routes/v1/mobile/plans.ts`
  - `server/src/routes/v1/mobile/plan.ts`
- 路由挂载点：
  - `server/src/routes/index.ts`
    - `router.use("/api/v1/mobile/plans", mobilePlansRouter)`
    - `router.use("/api/v1/mobile/plan", mobilePlanRouter)`
- 接口定义（建议）：
  - GET `/api/v1/mobile/plan/progress?goalId=...`
  - POST `/api/v1/mobile/plan/generate`
  - GET `/api/v1/mobile/plans`
  - POST `/api/v1/mobile/plans`
  - PATCH `/api/v1/mobile/plans/:id`
  - DELETE `/api/v1/mobile/plans/:id`
- 前端替换点：
  - `src/shared/constants/endpoints.ts` 对应函数改为真实 HTTP 请求。
  - `src/domains/analysis/api/analysis-api.ts` 无需改动导出关系，只要底层 endpoints 改为真实请求即可生效。

## P2（最后做，补齐体验与兼容）

### 5) 日流水聚合接口（若保留独立接口）
- 目标：将当前“交易列表映射”改回后端聚合接口，减轻前端拼装逻辑。

## 实施顺序建议
1. 先改后端路由挂载与接口实现（P0）。
2. 再替换前端 endpoints 中对应函数（P0）。
3. 补 P1 的画像与 NLP。
4. 最后决定是否保留前端聚合的 flows（P2）。
